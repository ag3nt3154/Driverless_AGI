## 🔴 Bugs & Critical Issues

### 1. `active_loop.plan_mode_exited` — Non-existent attribute (runtime crash)
**File:** [`cli.py:1212`](cli.py)

`cli.py` references `active_loop.plan_mode_exited` in the post-task check:
```python
if active_loop.plan_mode_exited and active_loop.exited_plan_file:
```
But `AgentLoop.__init__` (loop.py:303) only sets `self.exited_plan_file`. The `plan_mode_exited` field
was intentionally removed per session 17 (PROJECT_CONTEXT.md "2026-05-31 Bug"). This will raise
`AttributeError` whenever a plan mode session exits through the CLI REPL. The fix is to change the
condition to `if active_loop.exited_plan_file:`.

### 2. `SpawnCliSubagentTool` bypasses `_subagent_runner.py` entirely
**File:** [`tools/cli_subagent.py`](tools/cli_subagent.py)

`SpawnCliSubagentTool.run()` calls `subprocess.Popen` directly (lines 82–103) instead of reusing
`run_subagent()` from `tools/_subagent_runner.py`. Consequences:
- The spawned process is **never registered in `_active`**, so `extend_subagent_timeout` cannot
  extend its deadline (the tool exists but silently fails for custom subagents).
- **Stdout events are not relayed** to the TUI `ConversationPane` — no `on_event_factory` wiring.
- On timeout, `proc.terminate()` is called but the `prompt_file` / `task_file` temps may not be
  cleaned up if the finally block itself raises.

Fix: route through `run_subagent()` and accept an optional `on_event_factory` callback passed from
a new `on_event_factory` field on `SpawnCliSubagentTool`.

### 3. Temp file leak on subagent timeout
**File:** [`tools/_subagent_runner.py:131-133`](_subagent_runner.py)

```python
result = _poll_until(state, timeout)
if result["status"] != "timeout":
    task_file.unlink(missing_ok=True)
```
The temp task file is never deleted when `_poll_until` returns `"timeout"`. On a long session with
repeated timeout events, these accumulate in the system temp directory. Fix: always delete the temp
file, and track it inside `_SubagentState` so `resume_subagent` can clean it up after the process
finally exits.

### 4. `tempfile.mktemp()` is deprecated and insecure (TOCTOU)
**Files:** [`tools/_subagent_runner.py:96`](_subagent_runner.py), [`tools/cli_subagent.py:71,74`](tools/cli_subagent.py)

`tempfile.mktemp()` returns a filename without creating the file — a race condition between the
return and the caller's `write_text()`. Replace with `tempfile.NamedTemporaryFile(delete=False)` or
`tempfile.mkstemp()` and close the handle before passing the path to subprocess.

`AgentConfig` is defined in `agent/loop.py` but imported by `agent/config_loader.py` with a

### 9. Type-specific `_compose_*` logic in `spawn_subagent.py` — hardcoded and fragile
**File:** [`tools/spawn_subagent.py:49-108, 187-214`](tools/spawn_subagent.py)

`_compose_worker_context`, `_compose_explore_context`, `_compose_review_context` and the
`_compose_task` dispatch `if self._type_name == "worker" / "review" / "explore_files"` block are

## 🟡 Efficiency & Reliability

### 12. `SessionTracker._write()` opens a file on every call
**File:** [`agent/session.py:236-241`](agent/session.py)

Every JSONL record opens, appends, and closes the file. A long task with 200 tool calls makes 400+
file open/close syscalls. Fix: open the file handle once in `__init__` (or on first write) and keep
it open until `finish()` calls it. Use `try/finally` to guarantee flush+close. This also avoids
the small risk of data loss if the process crashes between the write and the OS flush.

---

### 13. `_poll_until` uses `time.sleep` — should use `proc.wait(timeout)`
**File:** [`tools/_subagent_runner.py:60-76`](_subagent_runner.py)

```python
while True:
    ret = proc.poll()
    ...
    time.sleep(_POLL_INTERVAL)
```
`proc.poll()` + `time.sleep` is a busy-wait. `proc.wait(timeout=_POLL_INTERVAL)` blocks in the OS
and avoids GIL pressure. The `try/except subprocess.TimeoutExpired` pattern is idiomatic Python:
```python
try:
    proc.wait(timeout=_POLL_INTERVAL)
    # process exited
except subprocess.TimeoutExpired:
    if time.monotonic() >= deadline:
        return {"status": "timeout", "pid": proc.pid}
```

### 14. No retry/backoff for transient API errors
**File:** [`agent/loop.py:364-390`](agent/loop.py)

A single 429 or 5xx error from the API raises an exception that propagates to `callbacks.on_error`
and terminates the task (per PROJECT_CONTEXT.md shortcomings). The ghost-response retry loop only
handles `content=None` cases, not HTTP errors. Add an outer retry with exponential backoff
(e.g., 2s, 4s, 8s) for `openai.RateLimitError` and `openai.APIStatusError` with status ≥ 500.
Cap retries at 3–5 attempts.

---

### 15. `CompactTool` always uses the current (possibly expensive) model for summarization
**File:** [`tools/compact.py:218-222`](tools/compact.py)

The summarization API call uses `config.model` — which may be the plan-tier advanced model during
plan mode, or the default model during normal operation. Summarization is a low-complexity task that
doesn't need the most capable model. If `worker_config` is available on the config, prefer it for
compaction. This can save meaningful cost on long sessions.

### 16. `AskUserTool.run()` spawns an unnecessary thread
**File:** [`tools/ask_user.py:88-96`](tools/ask_user.py)

```python
def _ask() -> None:
    result.append(self._on_ask_user(question, options, effective_timeout))

t = threading.Thread(target=_ask, daemon=True)
t.start()
t.join(timeout=effective_timeout)
```
The `on_ask_user` callback is already designed to block the calling thread (in TUI it uses a
`threading.Event`; in CLI it calls `console.input()`). Wrapping it in a thread + join with the
same timeout adds overhead and a subtle timing mismatch (the inner callback already has its own
timeout logic, so the join timeout doubles up). Call `self._on_ask_user` directly; the tool
already runs on the agent thread, not the UI thread.

## 🟢 UX & Completeness

### 17. Fix `/hist` in TUI — output goes to hidden scroll buffer
**File:** [`tui/commands.py`](tui/commands.py) (referenced in PROJECT_CONTEXT.md shortcomings)

`_cmd_hist()` calls `hist.run()` which writes to a bare `rich.Console`. In Textual this writes
behind the canvas to the terminal's alternate-screen hidden buffer — effectively invisible to the
user. Fix: read session records in the command handler and write them directly to `ConversationPane`
using `conv.write()` or `conv.append_info()`. The `hist.py` module's logic can be reused as a
data source while the rendering is redirected.

### 18. `PromptInput` has no visual cue during `ask_user` prompts
**File:** [`tui/app.py:207-217`](tui/app.py) (noted in PROJECT_CONTEXT.md shortcomings)

`PromptInput(TextArea)` has no `.placeholder` attribute, so the "Your answer…" cue was silently
dropped. When the agent calls `ask_user`, the user can see the question in `ConversationPane` but
there is no indicator on the input widget itself to distinguish it from a normal prompt.

Suggested fix: change `PromptInput`'s CSS `border-top` color while `_pending_ask` is set
(e.g., `border-top: solid $warning`). A single `call_from_thread(prompt_input.add_class, "asking")`
in `_show_ask_user` and `remove_class` in the submit handler achieves this with no new state.

### 19. Subagent pause — ESC only pauses parent loop, not subagent subprocess
**File:** [`tools/_subagent_runner.py`](tools/_subagent_runner.py) (noted in PROJECT_CONTEXT.md)

When the user presses ESC while a subagent is running, the parent loop pauses at its next
iteration checkpoint, but the child process runs unaffected. Add `proc.send_signal(signal.SIGSTOP)`
(POSIX) or `proc.terminate()` (cross-platform) as an option when `action_pause()` is called with
an active subagent. The `_active` dict already has the proc handle; the TUI `action_pause()` could
check `_active` and send the signal.
