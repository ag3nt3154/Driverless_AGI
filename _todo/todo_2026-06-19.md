## A. Bugs & Critical Issues

### A1. `_handle_switch_model` doesn't propagate `provider_order` from tier configs (Priority: HIGH)

**File:** [`agent/loop.py:720-727`](agent/loop.py:720)

When switching model tiers (default → plan → worker → default), `_handle_switch_model` rebuilds `self._extra_body` using `self.config.provider_order` (line 726). However, the tier configs (`advanced_config`, `worker_config`) are separate `AgentConfig` instances that may have their own `provider_order`. The method copies `model`, `base_url`, `api_key`, `thinking`, and `display_name` from the tier config (lines 713-717) but never copies `provider_order`.

This means if the advanced model (plan tier) has `provider_order: [Anthropic]` in its config entry but the default model has `provider_order: null`, switching to plan tier will use the default's `null` provider_order — no routing preference — instead of the advanced model's explicit preference.

**Impact:** Provider routing silently reverts to default (load-balanced) when switching tiers, even if the destination tier has an explicit `provider_order`. This could route Claude requests to unintended providers.

**Fix:** Add `self.config.provider_order = tier_cfg.provider_order` alongside the other field copies in `_handle_switch_model`:
```python
if tier_cfg is not None:
    self.config.model        = tier_cfg.model
    self.config.base_url     = tier_cfg.base_url
    self.config.api_key      = tier_cfg.api_key
    self.config.thinking     = tier_cfg.thinking
    self.config.display_name = tier_cfg.display_name
    self.config.provider_order = tier_cfg.provider_order  # ← ADD
```
Also add `provider_order` to `_base_config_snapshot` so the default tier can restore its own routing:
```python
self._base_config_snapshot: dict = {
    ...
    "provider_order": config.provider_order,  # ← ADD
}
```
And restore it in the `target == "default"` branch:
```python
self.config.provider_order = snap["provider_order"]
```

### A2. `_handle_switch_model` doesn't snapshot/restore `cache_prompt` (Priority: MEDIUM)

**File:** [`agent/loop.py:720-727`](agent/loop.py:720)

Same class of bug as A1. `cache_prompt` is used on line 724 (`if self.config.cache_prompt`) to decide whether to add `cache_prompt: True` to `_extra_body`. But it's never copied from tier configs and never included in `_base_config_snapshot`. If the default model has `cache_prompt: true` but the advanced model's config entry doesn't set it (defaults to `false`), switching tiers will keep using the stale value.

Currently benign because `cache_prompt` is read from the top-level config (not per-model), so all tiers share the same value. But this is a latent bug — if `cache_prompt` becomes per-model (like `provider_order` already is per-model), the value will silently persist across tier switches.

**Fix:** Include `cache_prompt` in the snapshot/restore pattern alongside `provider_order`.

### A3. `SpawnCliSubagentTool` does not use `_subagent_runner.run_subagent()` (Priority: MEDIUM)

**File:** [`tools/cli_subagent.py:80-110`](tools/cli_subagent.py:80)

`SpawnCliSubagentTool.run()` manually builds and runs a `subprocess.Popen` (lines 90-97) with a raw `proc.wait(timeout)` (line 100). This duplicates the subprocess management in `_subagent_runner.py` but without:
- **No stdout streaming**: The subagent's output is never relayed to the TUI. The parent sees nothing until the subagent finishes or times out.
- **No PID tracking in `_active`**: The process can't be resumed via `extend_subagent_timeout` after a timeout — `proc.terminate()` kills it immediately (line 102).
- **No event relay**: `on_subagent_event_factory` is never called, so no `[custom]` labels appear in the conversation pane.

Compare with `SpawnSubagentTool.run()` (lines 152-190 of `spawn_subagent.py`) which calls `run_subagent()` and gets all of these features.

**Impact:** Custom subagents are opaque — no streaming output, no resume capability, no TUI visibility. This makes `spawn_cli_subagent` significantly worse than the predefined subagent types.

**Fix:** Refactor `SpawnCliSubagentTool` to call `run_subagent()` from `_subagent_runner.py` instead of raw `subprocess.Popen`. The `--system-prompt-file` flag is already supported by `cli.py`'s subagent entry point, so the task composition just needs to pass the prompt file path through.

### B2. `_extra_body` rebuild is duplicated between `__init__` and `_handle_switch_model` (Priority: MEDIUM)

**Files:** [`agent/loop.py:310-316`](agent/loop.py:310), [`agent/loop.py:721-727`](agent/loop.py:721)

The `_extra_body` construction logic is identical in both locations:
```python
self._extra_body = {}
if config.thinking and config.thinking.lower() != "none":
    self._extra_body["reasoning"] = {"effort": config.thinking.lower()}
if config.cache_prompt:
    self._extra_body["cache_prompt"] = True
if config.provider_order:
    self._extra_body["provider"] = {"order": config.provider_order}
```

When a new OpenRouter extension is added (e.g., `transforms`, `route`, custom headers), it must be added in both locations or the feature silently breaks after a tier switch.

**Fix:** Extract `_build_extra_body() -> dict` method on `AgentLoop`:
```python
def _build_extra_body(self) -> dict:
    body: dict = {}
    if self.config.thinking and self.config.thinking.lower() != "none":
        body["reasoning"] = {"effort": self.config.thinking.lower()}
    if self.config.cache_prompt:
        body["cache_prompt"] = True
    if self.config.provider_order:
        body["provider"] = {"order": self.config.provider_order}
    return body
```

### C3. `_bm25_scores` recomputes IDF per-term per-document — O(N*Q*N) (Priority: LOW)

**File:** [`agent/memory_retriever.py:39-41`](agent/memory_retriever.py:39)

```python
for term in q_terms:
    n_q = sum(1 for t in tokenized if term in t)  # O(N) per term per doc
```

The `n_q` (document frequency) computation is inside the per-document loop but depends only on the term, not the current document. For K query terms and N documents, this is O(K*N) per document = O(K*N^2) total. With a wiki of 50+ pages and a 10-word query, this is 25,000 iterations.

**Fix:** Precompute document frequencies before the per-document loop:
```python
df = Counter()
for doc_tokens in tokenized:
    for unique_term in set(doc_tokens):
        df[unique_term] += 1
# Then in the per-doc loop:
n_q = df.get(term, 0)
```

if ext == ".pdf":
