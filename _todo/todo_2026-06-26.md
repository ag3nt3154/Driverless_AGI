## A. Bugs & Critical Issues

### A1. `_rebuild_for_reload` silently resets autonomous plan mode to interactive (Priority: MEDIUM — NEW)

**File:** [`agent/loop.py:909-912`](agent/loop.py:909)

```python
def _rebuild_for_reload(self, ...) -> ...:
    ...
    if self.config.plan_mode and self.config.plan_file:
        self._rebuild_for_plan_mode(dagi_root, Path(self.config.plan_file))
        #                                      ↑ no interactive= parameter
```

`_rebuild_for_plan_mode` has `interactive: bool = True` as default. When the agent is in **autonomous** plan mode (`plan_mode_initiated_by = "dagi"`) and triggers a skill reload, the rebuild silently resets `initiated_by` from `"dagi"` to `"user"` (via the default `interactive=True`).

This changes two behaviors:
1. `AskUserTool` timeout flips from 60s (auto-approve) to `None` (infinite wait) — the autonomous agent now blocks forever waiting for human input
2. `ShowPlanTool` `interactive` flag changes — auto-approve behavior is lost

**Impact:** After a skill reload during autonomous plan mode, the agent hangs indefinitely at the next `ask_user` call instead of auto-approving.

**Fix:**
```python
if self.config.plan_mode and self.config.plan_file:
    interactive = self.config.plan_mode_initiated_by == "user"
    self._rebuild_for_plan_mode(
        dagi_root, Path(self.config.plan_file), interactive=interactive,
    )
```

### A2. `build_subagent_registry` can't find configs when `project_path != DAGI_ROOT` (Priority: MEDIUM — NEW)

**File:** [`agent/tools.py:388-396`](agent/tools.py:388)

```python
def build_subagent_registry(subagent_type, config, project_path, ...):
    ...
    try:
        cfg = _load_subagent_config(subagent_type, project_path)
    except FileNotFoundError:
        raise ValueError(
            f"No subagent_config.yaml found for subagent_type={subagent_type!r}. "
            ...
        )
```

`_load_subagent_config` only checks `project_path / ".dagi" / "subagents"`. This function is called in the **subprocess** (child `cli.py --subagent-type`). When the parent spawns a worker/review subagent for a non-DAGI project, the child process crashes with `ValueError` because the project path doesn't have `.dagi/subagents/worker/subagent_config.yaml`.

This is a different code path from the parent-side A3 issue (2026-06-25) which is about `_discover_subagent_tools`. Both share the same root cause: `_load_subagent_config` doesn't fall back to `DAGI_ROOT`.

**Impact:** ALL subagent spawning is broken for non-DAGI projects — worker, review, explore_files, and web_research subagents all crash immediately. The plan-work-review skill is completely non-functional when `--project` points elsewhere.

**Fix:** Add DAGI_ROOT fallback to `_load_subagent_config`:
```python
def _load_subagent_config(subagent_type: str, project_path: Path) -> dict:
    for base in (project_path, _DAGI_ROOT):
        config_path = base / ".dagi" / "subagents" / subagent_type / "subagent_config.yaml"
        if config_path.exists():
            return yaml.safe_load(config_path.read_text(encoding="utf-8")) or {}
    raise FileNotFoundError(f"No subagent_config.yaml for {subagent_type!r}")
```

### A3. `ToolRegistry.dispatch()` swallows system-level exceptions (Priority: LOW — NEW)

**File:** [`agent/registry.py:29-35`](agent/registry.py:29)

```python
def dispatch(self, name: str, kwargs: dict) -> str | list:
    if name not in self._tools:
        return f"Error: unknown tool '{name}'"
    try:
        return self._tools[name].run(**kwargs)
    except Exception as e:
        return f"Error: {e}"
```

The broad `except Exception` catches everything including `MemoryError`, `RecursionError`, and `KeyboardInterrupt`-derived exceptions (in Python 3.11+, `KeyboardInterrupt` doesn't inherit from `Exception`, but `RecursionError` and `MemoryError` do). A tool that runs out of memory would silently produce `"Error: ..."` as a tool result instead of crashing the process.

For normal tool errors (file not found, bad arguments) this is correct — the LLM sees the error and can adjust. But system-level failures (`MemoryError`, `RecursionError`) should propagate to the outer loop's exception handler.

**Fix:**
```python
try:
    return self._tools[name].run(**kwargs)
except (MemoryError, RecursionError):
    raise
except Exception as e:
    return f"Error: {e}"
```

## B. Code Simplification & Architecture

### B1. `_bm25_scores` has quadratic doc-frequency calculation (Priority: LOW — NEW)

**File:** [`agent/memory_retriever.py:39-41`](agent/memory_retriever.py:39)

```python
for doc_tokens in tokenized:
    ...
    for term in q_terms:
        n_q = sum(1 for t in tokenized if term in t)  # ← O(N) per term per doc
```

The document-frequency calculation `n_q` iterates all `N` documents for every query term for every document being scored. This makes the scoring loop O(N² × M) where N=documents and M=query terms.

**Impact:** Negligible for current wiki sizes (<50 pages). Would become noticeable at 500+ pages.

**Fix:** Precompute the df lookup once before the scoring loop:
```python
df = {}
for term in q_terms:
    df[term] = sum(1 for t in tokenized if term in t)

for doc_tokens in tokenized:
    ...
    for term in q_terms:
        n_q = df[term]
```

## D. New Features & Capabilities

### D1. Structured error context for tool failures (Priority: MEDIUM — NEW)

Currently, `ToolRegistry.dispatch()` catches exceptions and returns `f"Error: {e}"`. The LLM has no structured information about what went wrong — no exception type, no traceback snippet, no suggested retry strategy.

Adding structured error context would let the agent make better decisions:
```python
return f"Error [{type(e).__name__}]: {e}"
```

This is a minimal change that gives the LLM the exception class name, enabling pattern-matching on `FileNotFoundError` vs `PermissionError` vs `TimeoutError`.

### D2. Token-efficient system prompt rebuild (Priority: MEDIUM — NEW)

All three rebuild methods (`__init__`, `_rebuild_for_normal_mode`, `_rebuild_for_plan_mode`) reconstruct the full system prompt from scratch — re-reading files from disk, re-formatting the tools+skills section, re-building the preamble. In a session with multiple plan mode transitions, the same files are read 3-4 times.

A `_cached_prompt_parts` dict that caches the static components (soul.md, agents.md, main_system.md) and only regenerates the dynamic parts (tools list, plan file reference) would reduce disk I/O and string allocation during transitions. This ties into the B2 "unified rebuild" refactor.
