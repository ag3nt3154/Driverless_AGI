### A1. `_subagent_runner.py` also has pipe buffer deadlock when `on_event is None` (Priority: HIGH — NEW)

**File:** [`tools/_subagent_runner.py:108-128`](tools/_subagent_runner.py:108)

The 2026-06-25 morning review (A2) flagged `SpawnCliSubagentTool` for the pipe deadlock pattern. However, `_subagent_runner.py` — the "correct" subagent runner — has the **same bug** in CLI mode:

```python
proc = subprocess.Popen(
    argv,
    stdout=subprocess.PIPE,   # ← pipe captured
    stderr=subprocess.STDOUT,
    ...
)
# ...
if on_event:                    # ← ONLY starts drain thread when on_event is set
    t = threading.Thread(target=_stream_stdout, args=(proc, on_event), daemon=True)
    t.start()
```

In CLI mode, `AgentCallbacks.on_subagent_event_factory` defaults to `None`. The `SpawnSubagentTool` passes `on_event=None`, so **no drain thread starts**. `_poll_until()` only calls `proc.poll()` — it never reads from the pipe.

If the subagent writes >64KB to stdout (common for verbose sessions with tool output), the OS pipe buffer fills, the child blocks on `write()`, and `proc.poll()` returns `None` indefinitely. The timeout eventually fires, but the subagent hangs for the full timeout period (default 300s) rather than making progress.

**Impact:** Every subagent spawned from CLI mode (not TUI) is vulnerable to pipe deadlock on verbose output. The TUI is unaffected because `on_subagent_event_factory` is always set.

**Fix:** Always start the drain thread, even when `on_event` is `None`. When no callback is needed, drain to `/dev/null`:

```python
def _drain_only(proc: subprocess.Popen) -> None:
    """Read stdout lines to prevent pipe buffer deadlock (runs in daemon thread)."""
    try:
        for _ in proc.stdout:
            pass
    except Exception:
        pass

# In run_subagent():
if on_event:
    t = threading.Thread(target=_stream_stdout, args=(proc, on_event), daemon=True)
else:
    t = threading.Thread(target=_drain_only, args=(proc,), daemon=True)
t.start()
```

### A2. `SkillTool.run()` reloads all skills from disk on every invocation (Priority: MEDIUM — NEW)

**File:** [`tools/skill.py:41-46`](tools/skill.py:41)

```python
def run(self, skill: str) -> str:
    from agent.skills import SkillLoader
    skills_map = {
        s.name: s
        for s in SkillLoader().load_all(self._skill_roots, dagi_root=self._dagi_root)
    }
```

Every `skill("name")` call:
1. Creates a new `SkillLoader` instance
2. Scans all skill root directories recursively (`rglob("SKILL.md")`)
3. Reads every SKILL.md file from disk
4. Parses YAML frontmatter for each
5. Builds the complete skills map
6. Looks up the requested skill by name

`AgentLoop` already has `self.skills` — the pre-loaded skills list. But `SkillTool` has no reference to it. Instead it re-discovers everything from disk on every call.

**Impact:** Unnecessary disk I/O and CPU on every skill invocation. With 15+ skills across two roots, this is ~30 file reads per call. In a session with 5+ skill invocations, that's 150+ redundant file reads.

**Fix:** Pass the pre-loaded skills list to `SkillTool` at construction time, or cache after first load:

```python
class SkillTool(BaseTool):
    def __init__(self, ..., skills: list[Skill] | None = None):
        self._cached_skills = {s.name: s for s in skills} if skills else None

    def run(self, skill: str) -> str:
        if self._cached_skills is None:
            self._cached_skills = {
                s.name: s
                for s in SkillLoader().load_all(self._skill_roots, ...)
            }
        ...
```

Note: `reload_skills` already rebuilds the registry (which creates a new `SkillTool`), so caching wouldn't prevent hot-reload.

### A3. `session_end` JSONL record dumps full `raw_messages` including base64 images (Priority: HIGH — NEW)

**Files:** [`agent/session.py:213-214`](agent/session.py:213), [`agent/loop.py:918`](agent/loop.py:918)

```python
# session.py
if raw_messages is not None:
    record["raw_messages"] = raw_messages

# loop.py
self.tracker.finish(raw_messages=self._messages)
```

`self._messages` is the complete conversation history including all tool results. When `ReadTool` reads an image, the result is a list containing base64-encoded data (~32KB per image). Every image ever read during the session is preserved in `_messages` and dumped into the `session_end` record as a single JSONL line.

A session with 5 images produces a `session_end` line of 160KB+. Over 198 session files, this is a significant contributor to log bloat — and the data is already recorded as individual `tool_end` records in the same JSONL file.

**Impact:** Log bloat, slow log parsing, and redundant data storage. The `raw_messages` field is primarily used for post-session analysis, but the individual turn records already capture the same information.

**Fix:** Either:
- (a) Strip image data from `raw_messages` before writing: replace list-typed content with `"[image data omitted]"`
- (b) Stop passing `raw_messages` entirely — the individual turn records are authoritative
- (c) Truncate `raw_messages` content to a max size per message

### A4. `WebFetchTool` silently upgrades HTTP→HTTPS for private IPs (Priority: MEDIUM — NEW)

**File:** [`tools/web_fetch.py:123`](tools/web_fetch.py:123)

```python
if url.startswith("http://") and "localhost" not in url and "127.0.0.1" not in url:
    url = "https://" + url[7:]
```

The exclusion only covers `localhost` and `127.0.0.1`. Private network addresses are not excluded:
- `http://192.168.1.100:8080` → silently upgraded to HTTPS → connection failure
- `http://10.0.0.5:3000` → same
- `http://0.0.0.0:5000` → same
- `http://[::1]:8080` → same (IPv6 loopback)

**Impact:** Agent fails to fetch content from local development servers on private network addresses. The error message (`failed to fetch {url}`) includes the HTTPS URL, obscuring the root cause.

**Fix:** Expand the exclusion list:

```python
import re
_LOCAL_PATTERNS = re.compile(
    r"localhost|127\.\d+\.\d+\.\d+|0\.0\.0\.0|"
    r"10\.\d+\.\d+\.\d+|172\.(1[6-9]|2\d|3[01])\.\d+\.\d+|"
    r"192\.168\.\d+\.\d+|\[::1\]"
)
if url.startswith("http://") and not _LOCAL_PATTERNS.search(url):
    url = "https://" + url[7:]
```

### A5. `WebSearchTool` domain filtering uses substring matching (Priority: LOW — NEW)

**File:** [`tools/web_search.py:53-55`](tools/web_search.py:53)

```python
if allowed_domains and not any(d in url for d in allowed_domains):
    continue
if blocked_domains and any(d in url for d in blocked_domains):
    continue
```

`d in url` is a substring check. `allowed_domains=["example.com"]` matches `badexample.com` or `example.com.evil.net`. `blocked_domains=["ads"]` blocks `https://spreadsheets.google.com/`. Unlikely to cause issues in practice, but a correctness gap.

**Fix:** Use `urllib.parse.urlparse(url).hostname.endswith("." + d) or hostname == d` for proper domain matching.
