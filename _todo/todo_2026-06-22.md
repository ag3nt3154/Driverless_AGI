## A. Bugs & Critical Issues

### A1. `_rebuild_for_plan_mode` missing `bash_tool=` in `create_tool_registry` call (Priority: HIGH — NEW)

**File:** [`agent/loop.py:852-863`](agent/loop.py:852)

The three `create_tool_registry` call sites have an asymmetry:
- `__init__` (line 262): passes `bash_tool=_bash_tool` **correct**
- `_rebuild_for_normal_mode` (line 790): passes `bash_tool=self._injected_bash_tool` **correct**
- `_rebuild_for_plan_mode` (line 852-863): does **NOT** pass `bash_tool=` **BUG**

This is the same class of divergence bug as the `memory_root` omission (A3 below). When entering plan mode in a benchmark context (Harbor / Terminal-bench) where `_bash_tool` was injected, the injected bash tool is silently lost from the registry. The standard `BashTool(cwd)` is always registered, so this only affects the *additional* injected tool (e.g. `HarborBashTool`, `TmuxBashTool`).

**Impact:** In benchmark runs, entering plan mode drops the `harbor_bash` or `tmux_bash` tool from the registry. The agent can no longer reach the Docker container until it exits plan mode.

**Fix:**
```python
self.registry = create_tool_registry(
    ...
    memory_root=self._effective_memory_root,
    bash_tool=self._injected_bash_tool,  # ← add this line
)
```

### A4. Plan skeleton code doesn't include `## Execution Protocol` heading (Priority: MEDIUM — NEW)

**File:** [`agent/loop.py:616-631`](agent/loop.py:616)

The plan scaffold written by `_handle_enter_plan_mode` includes headings for Context, Approach, Files to Modify, Subtasks, Notes, and Verification — but NOT `## Execution Protocol`. The plan-work-review SKILL.md template (Step 5) includes this section, and the agent is supposed to write it when filling in the plan. However, if the skill instructions are compacted before the agent writes the plan, it won't know to include this section.

The entire point of the 2026-06-21 fix was to make the Execution Protocol compaction-immune by writing it to disk. But the code-generated scaffold doesn't include the heading, so it relies on the agent's memory of the skill template — the very problem the fix was designed to solve.

**Fix:** Add `"## Execution Protocol\n\n"` to the scaffold at line 631:
```python
        "## Verification\n\n"
        "## Execution Protocol\n\n",
        encoding="utf-8",
    )
```

This ensures the heading is always present in the plan skeleton. If the agent writes a full plan with the Execution Protocol content, this empty heading gets overwritten. If compaction erases the skill instructions before the agent writes the plan, the heading is still there as a structural cue.
