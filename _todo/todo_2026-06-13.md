### 2. `tempfile.mktemp()` — TOCTOU race and deprecation (persistent from #4)
**Files:** [`tools/_subagent_runner.py:96`](tools/_subagent_runner.py), [`tools/cli_subagent.py:70,73`](tools/cli_subagent.py)

`tempfile.mktemp()` returns a filename without atomically creating it. A malicious process (or
even a parallel DAGI session) can create a file at that path between the `mktemp()` call and
the subsequent `write_text()`. This is a documented security vulnerability (TOCTOU).

Fix:
```python
# _subagent_runner.py
fd, task_path = tempfile.mkstemp(suffix=".txt", prefix="dagi_task_")
os.close(fd)
task_file = Path(task_path)
task_file.write_text(task, encoding="utf-8")
```
Apply the same pattern to both files. Also track `task_file` in `_SubagentState` (see #3).

### 3. Temp file leak on subagent timeout (persistent from #3)
**File:** [`tools/_subagent_runner.py:131`](tools/_subagent_runner.py)

```python
result = _poll_until(state, timeout)
if result["status"] != "timeout":
    task_file.unlink(missing_ok=True)  # ← never called on timeout
```
The temp task file is never cleaned up when `_poll_until` returns `"timeout"`. Long sessions
with repeated timeouts accumulate temp files indefinitely.

Fix: Add `task_file: Path` to `_SubagentState`; delete it in `_poll_until` when the process
finally exits (including after `resume_subagent` calls). As a belt-and-suspenders measure, also
register a `tempfile.TemporaryDirectory` or `atexit` cleanup.

### 5. `AgentConfig` circular import — circular comment still present (persistent from #7)
**File:** [`agent/config_loader.py:26`](agent/config_loader.py)

```python
# Imported here to avoid a circular import — config_loader must not import AgentLoop.
from agent.loop import AgentConfig
```
`AgentConfig` and `AgentCallbacks` are pure dataclasses with zero side effects; they belong in
their own module (`agent/config.py`). Both `loop.py` and `config_loader.py` would then import

additions to `AgentConfig` risk accidentally pulling in `AgentLoop` transitive deps.

### 12. `WorkflowLoader.rglob("workflow.md")` finds workflows at any depth
**File:** [`agent/workflows.py:62`](agent/workflows.py)

```python
for wf_file in sorted(root.rglob("workflow.md")):
```
`rglob` recurses into ALL subdirectories — including `.git/`, any archived or draft folders,
or user project subdirectories that happen to contain `workflow.md`. This is different from
the skills loader which uses a flat `*/SKILL.md` pattern. Use `glob("*/workflow.md")` (one
level deep only) or `glob("**/workflow.md")` with explicit exclude patterns for `.git` etc.

## 🟡 Efficiency & Reliability

### 13. `SessionTracker._write()` opens file on every call (persistent from #12)
**File:** [`agent/session.py:236-241`](agent/session.py)

```python
def _write(self, record: dict) -> None:
    if self._parent is not None:
        self._parent._write(record)
    else:
        with open(self._path, "a", encoding="utf-8") as fh:  # ← opened every call
            fh.write(...)
```
A task with 200 tool calls makes 400+ open/close syscalls. Keep the file handle open from
`__init__` to `finish()`. Use `try/finally` around the `_write` consumer to guarantee
`fh.flush(); fh.close()` on teardown. This also prevents data loss on crash (OS still buffers,
but a single `fh.flush()` in `finish()` is safer than 400 individual opens).

### 14. `_poll_until` uses busy `time.sleep` (persistent from #13)
**File:** [`tools/_subagent_runner.py:64-76`](tools/_subagent_runner.py)

`proc.poll()` + `time.sleep(2.0)` holds the GIL every 2 seconds. `proc.wait(timeout=2.0)` is
idiomatic and OS-efficient:
```python
try:
    proc.wait(timeout=_POLL_INTERVAL)
    # process exited — check handoff
except subprocess.TimeoutExpired:
    if time.monotonic() >= deadline:
        return {"status": "timeout", "pid": proc.pid}
    continue
```

### 16. `AskUserTool.run()` spawns an unnecessary thread (persistent from #16)

### 20. ESC pause doesn't propagate to subagent subprocess (persistent from #19)
**File:** [`tui/app.py:114-131`](tui/app.py), [`tools/_subagent_runner.py`](tools/_subagent_runner.py)

ESC pauses the parent loop at its next iteration checkpoint, but any running subagent subprocess
continues unaffected. The `_active` dict in `_subagent_runner.py` has the proc handle.

Fix: in `action_pause()`, after `loop.pause()`, iterate `_active` and call
`proc.send_signal(signal.SIGSTOP)` on POSIX (or `proc.terminate()` cross-platform as a softer
option). Resume would call `proc.send_signal(signal.SIGCONT)` or let the subagent drain.

## 🟣 New Features

### 24. GNHF tooling — agent-writable self-improvement log
Add a `GnhfNoteTool` that lets the agent explicitly record self-improvement observations to
`.dagi/gnhf/notes.md`. Schema:
```json
{
  "observation": "...",
  "category": "mistake|success|pattern|improvement",
  "context": "optional free text"
}
```
The tool appends a timestamped Markdown entry to the notes file. Future sessions can then load
top-N notes via the skill system or BM25 retrieval — closing the GNHF loop without human
transcription. This makes the project's stated self-improvement objective actionable.

---

### 25. PDF reading tool
Add `ReadPdfTool` using `pdfplumber` (already in many Python envs) or `pypdf`:
```python
class ReadPdfTool(BaseTool):
    name = "read_pdf"
    description = "Extract text from a PDF file by page range."
```
Accept `path`, optional `pages` (e.g. `"1-5"` or `"3"`), and optional `extract_tables: bool`.
Many real-world tasks involve PDFs (research papers, API docs, vendor specs). Without this tool,
the agent's only option is `bash("pdftotext ...")` which is fragile and unavailable on Windows.

---

### 26. Session analytics command / skill
Add a `dagi analyze-sessions` CLI command (or a `.dagi/skills/analyze-sessions/` skill) that
reads the JSONL logs and produces per-task statistics:
- Average tokens per task, cost per task
- Most-used tools (with frequency histogram)
- Task duration distribution
- Continuation count distribution (measure how often the agent stalls)
- Compaction frequency

This is directly actionable for measuring and improving token efficiency — the project's stated
benchmark goal. The data is already in `.dagi/logs/*.jsonl`.

---

### 27. Streaming responses
The TUI currently only updates sidebar token counts and renders assistant text after each full
API response. Streaming would:
- Surface tokens incrementally in the sidebar (better progress feedback)
- Start rendering assistant text as it arrives (lower perceived latency)

Implementation: use `stream=True` in `client.chat.completions.create(...)`, replace
`response.choices[0].message` consumption with chunk accumulation. The `on_assistant_text`
callback would be called per-chunk instead of once. Most of the logic fits in ~30 lines.

---

### 28. `/search` command — semantic search over past session logs
Add a `/search <query>` slash command in TUI and CLI that runs BM25 retrieval over
`.dagi/logs/*.jsonl` to surface relevant past task contexts. The memory retriever in
`agent/memory_retriever.py` already implements BM25; the index source would just be session
logs instead of wiki files. This enables "what did I do last time I worked on X?" queries
without reading all logs manually.

---

### 29. Auto-extend subagent timeout via skill
When `spawn_*_subagent` times out, the agent must manually call `extend_subagent_timeout`.
This is error-prone — models sometimes forget or call the wrong tool. Add a
`auto_extend_subagent_on_timeout: true` config key and a corresponding loop-level handler:
when a tool result contains `{"status": "timeout", "pid": N}`, automatically call
`resume_subagent(pid, extra_seconds)` up to `max_subagent_extensions` (default 2). Surface
the extension in the conversation pane as an info message. The agent loop already has all the
information needed; no new subprocess logic required.

---

### 30. Model benchmarking harness — token efficiency measurement
Add a `scripts/bench_model.py` script that:
1. Takes a set of canned tasks (stored in `.dagi/benchmarks/tasks/`) and a list of model IDs
2. Runs each task through `AgentLoop` with each model
3. Records tokens, cost, tool calls, and success/failure to a JSONL results file
4. Prints a comparison table

This directly measures token efficiency across model tiers — the stated project objective.
Even 5–10 canned tasks would give enough signal to compare `default_model` vs. `worker_model`
and tune `max_continuations` / `context_window` per model.
