### A2. `SpawnCliSubagentTool.run()` pipe buffer deadlock risk (Priority: HIGH — NEW, escalation of 2026-06-19 A3)

**File:** [`tools/cli_subagent.py:90-100`](tools/cli_subagent.py:90)

```python
proc = subprocess.Popen(
    argv,
    stdout=subprocess.PIPE,   # ← pipe captured
    stderr=subprocess.STDOUT,
    ...
)
try:
    proc.wait(timeout=float(timeout))  # ← blocks until exit
except subprocess.TimeoutExpired:
    proc.terminate()
```

Python's own docs warn: *"This will deadlock when using `stdout=PIPE` and the child process generates enough output to a pipe such that it blocks waiting for the OS pipe buffer to accept more data."*

The pipe buffer is typically 64KB on Windows and Linux. If the custom subagent produces more than 64KB of stdout (common for verbose agent sessions with tool call output), the child blocks on `write()`, the parent blocks on `wait()`, and both hang forever. The timeout will eventually fire, but the deadlock window is the entire timeout period (default 300s).

Compare with `_subagent_runner.py` which correctly spawns a daemon thread to drain stdout (`_stream_stdout`), preventing buffer saturation.

**Impact:** Custom subagents that produce verbose output will intermittently hang for the full timeout duration, then get killed.

**Fix:** Either:
- (a) Use `proc.communicate(timeout=timeout)` (Python drains the pipe)
- (b) Add a `_stream_stdout` drain thread like `_subagent_runner.py`
- (c) Best: migrate `SpawnCliSubagentTool` to use `_subagent_runner.run_subagent()` directly (eliminates all duplicated subprocess management)

### A3. Subagent discovery only scans project path, misses dagi root types (Priority: MEDIUM — NEW)

**Files:** [`agent/tools.py:84-133`](agent/tools.py:84) (`_discover_subagent_tools`), [`agent/tools.py:43-48`](agent/tools.py:43) (`_load_subagent_config`)

Both functions only look at `cwd / ".dagi" / "subagents"` where `cwd = config.project_path`:

```python
def _discover_subagent_tools(cwd, ...):
    subagents_dir = cwd / ".dagi" / "subagents"  # ← only project path
    ...

def _load_subagent_config(subagent_type, project_path):
    config_path = project_path / ".dagi" / "subagents" / ...  # ← only project path
```

DAGI's own subagent types (worker, review, explore_files, web_research) live at `DAGI_ROOT / ".dagi" / "subagents"`. When `project_path != DAGI_ROOT` (after `/wd` or `--project`), the subagent tools silently disappear from the registry.

Contrast with `SpawnSubagentTool._load_parameters()` which correctly searches **both** paths:
```python
search_paths = [
    _DAGI_ROOT / ".dagi" / "subagents" / type_name / "subagent_config.yaml",
]
if isinstance(proj, Path):
    search_paths.insert(0, proj / ".dagi" / "subagents" / ...)
```

**Impact:** When working on a non-DAGI project, `spawn_worker_subagent`, `spawn_review_subagent`, `spawn_explore_files_subagent`, and `spawn_web_research_subagent` all silently vanish. The plan-work-review skill becomes non-functional.

**Fix:** `_discover_subagent_tools` should scan both `_DAGI_ROOT / ".dagi" / "subagents"` and `cwd / ".dagi" / "subagents"` (project types override dagi root types on name collision). Similarly, `_load_subagent_config` should fall back to `_DAGI_ROOT` when the project path has no config.

## C. Token Efficiency & Self-Improvement

### C1. `_estimate_tokens` also hits the base64 `str()` problem (Priority: HIGH — NEW, same class as C2)

**File:** [`tools/compact.py:45-52`](tools/compact.py:45)

```python
def _estimate_tokens(msg: dict) -> int:
    text = ""
    if msg.get("content"):
        text += str(msg["content"])  # ← list → Python repr with base64
```

When `content` is a list (image tool results), `str(content)` produces `[{'type': 'image_url', 'image_url': {'url': 'data:image/png;base64,iVBOR...'}}]` — potentially 32K+ characters.

This inflates the token estimate by ~8K tokens per image message. Since `_estimate_tokens` determines the tail boundary for compaction (`keep_recent_tokens`), overestimating means the "recent tail" is shorter than intended — **less context is preserved during compaction**.

**Fix:** Same pattern as C2 — guard with `isinstance(content, list)` and use a placeholder token count (e.g., 200 tokens per image).
